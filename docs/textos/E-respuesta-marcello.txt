Thanks @marcellourbani — invitation accepted, and count us in as maintainers, not just as a base.

On your two hesitations, with facts rather than promises:

**Compatibility.** The JetBrains support is *additive*: every REST Client file runs unchanged. Nothing was removed or renamed in the format, `rest-client.*` settings are still read, and history/cookies/environments come from the same `~/.rest-client` folder. What was added are things that did not exist before (`http-client.env.json`, `import`, `run #name`, `{{$secret}}`, `# @assert`, `WEBSOCKET`, `text/event-stream` painted live) — a file that does not use them is not affected. The 52 tests include 28 integration tests that send real requests through the extension against a local server, most of them written to pin REST Client's existing behaviour (variables, environments, redirects, cookies, localhost/IPv6, JSONPath/XPath request variables) before touching anything. The two upstream PRs I rejected were rejected *because* they broke compatibility (#1396 broke `localhost`) or safety (#532 ran shell commands from the file).

**Documentation.** You are right that the README became a pitch. Huachao's full reference is now back, verbatim, in [docs/REFERENCE.md](https://github.com/TecniartGalicia/httpkeeper/blob/master/docs/REFERENCE.md), and the README links to it. If the org prefers it as the README itself, that is a five-minute change.

**For the org repo**, my proposal: base it on HttpKeeper's `master` (proper fork, history intact, CI on three OSes, 0 vulnerabilities, release workflow that publishes to the Marketplace, Open VSX, npm and GitHub in one tag), and graft what @tutilus did that we lack — the CI/CD and docs split, the UX fixes and the syntax-colouring work. I am glad to open that as PRs against the org repo once it is bootstrapped, and to keep maintaining there. Publishing identity (which publisher, whether `argalla.httpkeeper` stays as the published build or we move to an org publisher) is worth its own issue; I have no attachment to the name, only to not stranding the people who already installed.

Whatever base you pick, keep Huachao's copyright line and the MIT text as they are in our LICENSE.
